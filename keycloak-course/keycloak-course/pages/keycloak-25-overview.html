Keycloak 25 overview

Keycloak 25 est un serveur IAM orienté standards, conçu pour centraliser l’authentification, le SSO, la fédération d’identité et l’émission de tokens.

Ce qu’il faut savoir sur Keycloak 25

Cette version introduit notamment le support Java 21, confirme la direction cloud-native du produit et continue de pousser les intégrations standards plutôt que les anciens adapters propriétaires.

Attention

Ne construis pas une architecture dépendante d’anciens adapters spécifiques supprimés ou déconseillés. Favorise le support standard OIDC/OAuth2 des frameworks et reverse proxies.

Cycle de vie d’une authentification

1. Le client redirige l'utilisateur vers Keycloak
2. Keycloak exécute un authentication flow
3. L'utilisateur s'authentifie (mot de passe, OTP, WebAuthn...)
4. Keycloak crée/associe une session SSO
5. Keycloak émet les tokens
6. Le client utilise le token pour appeler l'API
7. L'API valide issuer, audience, signature, expiration et rôles

Tokens émis

Définition

Access token : sert à appeler une API.
ID token : décrit l’authentification de l’utilisateur pour le client.
Refresh token : permet d’obtenir de nouveaux tokens sans relogin immédiat.

{
  "iss": "https://sso.example.com/realms/acme",
  "sub": "0d42a6...",
  "aud": "finance-api",
  "azp": "web-portal",
  "scope": "openid profile email",
  "realm_access": {
    "roles": ["user", "manager"]
  },
  "resource_access": {
    "finance-api": {
      "roles": ["invoice:read", "invoice:approve"]
    }
  }
}
Piège fréquent

Utiliser l’ID token pour appeler une API. Une API attend en général un access token, pas un ID token.
