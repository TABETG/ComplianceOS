Services métier

La SPA déclenche le login, reçoit des tokens via Authorization Code + PKCE, puis appelle l’API avec un bearer token.

Exemple Spring Security Resource Server

spring:
  security:
    oauth2:
      resourceserver:
        jwt:
          issuer-uri: https://sso.example.com/realms/acme

@Configuration
@EnableWebSecurity
public class SecurityConfig {

    @Bean
    SecurityFilterChain securityFilterChain(HttpSecurity http) throws Exception {
        http
            // Toute requête vers /api/admin/** exige le rôle admin
            .authorizeHttpRequests(auth -> auth
                .requestMatchers("/api/admin/**").hasRole("admin")
                .requestMatchers("/api/invoices/**").hasAnyRole("user", "manager")
                .anyRequest().authenticated()
            )
            // L'API se comporte comme un Resource Server JWT
            .oauth2ResourceServer(oauth2 -> oauth2.jwt());

        return http.build();
    }
}

Point important : il faut souvent ajouter un convertisseur pour mapper proprement les rôles Keycloak vers les autorités Spring.

Mapping des rôles Keycloak

@Bean
JwtAuthenticationConverter jwtAuthenticationConverter() {
    JwtGrantedAuthoritiesConverter scopes = new JwtGrantedAuthoritiesConverter();
    scopes.setAuthorityPrefix("SCOPE_");

    JwtAuthenticationConverter converter = new JwtAuthenticationConverter();
    converter.setJwtGrantedAuthoritiesConverter(jwt -> {
        Collection<GrantedAuthority> authorities = new ArrayList<>(scopes.convert(jwt));

        Map<String, Object> realmAccess = jwt.getClaim("realm_access");
        if (realmAccess != null && realmAccess.get("roles") instanceof Collection<?> roles) {
            for (Object role : roles) {
                authorities.add(new SimpleGrantedAuthority("ROLE_" + role));
            }
        }
        return authorities;
    });
    return converter;
}
Bonne pratique

Teste explicitement le mapping réel de tes tokens. N’assume jamais que hasRole("admin") marchera sans adaptation.

Microservices

Deux approches reviennent souvent :

  • Validation locale JWT dans chaque service : rapide, robuste, moins de dépendance runtime.
  • API Gateway qui centralise une partie du contrôle : utile mais ne remplace pas totalement la sécurité interne.
Attention

Ne délègue pas toute la sécurité au frontend. La vérification décisive doit rester côté backend/API.
