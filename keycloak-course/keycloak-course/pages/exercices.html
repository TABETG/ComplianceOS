Lecture de JWT

{
  "aud": "finance-api",
  "azp": "web-portal",
  "realm_access": { "roles": ["user"] },
  "resource_access": {
    "finance-api": { "roles": ["invoice:approve"] }
  }
}
Questions

Ce token peut-il théoriquement appeler finance-api ? Quel rôle fin semble présent ? Quel client a initié l’authentification ?

Corrigés

Corrigé QCM

QCM 1 : B. QCM 2 : B.

Corrigé Cas 1

React = public client, Authorization Code + PKCE, l’API valide localement les JWT via l’issuer et les clés publiées.

Corrigé Cas 2

Activer du MFA fort, idéalement WebAuthn/FIDO2, au minimum pour les administrateurs.

Corrigé Cas 3

Tu perds en granularité, tu gonfles les tokens, tu mélanges les responsabilités et tu rends l’évolution applicative plus difficile.

Corrigé lecture JWT

aud=finance-api indique la cible prévue. Le rôle fin présent semble être invoice:approve. Le client initiateur semble être web-portal via azp.
