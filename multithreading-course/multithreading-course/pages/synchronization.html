Synchronisation et coordination

Locks, sémaphores, conditions, barrières, queues et patterns producteur/consommateur en Java et Python.

1. Introduction

La synchronisation et la coordination servent à garantir que plusieurs threads accèdent correctement à une ressource partagée ou progressent dans un ordre attendu.

2. Niveau débutant

Exclusion mutuelle

Quand une ressource ne peut être modifiée correctement que par un seul thread à la fois, on utilise un lock.

Producteur / consommateur

Un thread produit des tâches, un autre les consomme. Les files bloquantes sont idéales pour ce pattern.

// Java - producteur / consommateur avec BlockingQueue
import java.util.concurrent.*;

public class ProducerConsumer {
    public static void main(String[] args) {
        BlockingQueue queue = new ArrayBlockingQueue<>(10);

        ExecutorService executor = Executors.newFixedThreadPool(2);

        executor.submit(() -> {
            for (int i = 0; i < 5; i++) {
                queue.put("job-" + i);
            }
            queue.put("STOP");
            return null;
        });

        executor.submit(() -> {
            while (true) {
                String item = queue.take();
                if ("STOP".equals(item)) break;
                System.out.println("Traitement: " + item);
            }
            return null;
        });

        executor.shutdown();
    }
}

# Python - producteur / consommateur avec Queue
from queue import Queue
from threading import Thread

queue = Queue()

def producer():
    for i in range(5):
        queue.put(f"job-{i}")
    queue.put("STOP")

def consumer():
    while True:
        item = queue.get()
        if item == "STOP":
            break
        print("Traitement:", item)

Thread(target=producer).start()
Thread(target=consumer).start()

3. Niveau intermédiaire

Choisir la bonne primitive

  • Lock : protection simple.
  • Condition : attente conditionnelle.
  • Semaphore : limiter le débit d’accès.
  • Queue : communication sûre et découplage.

Pièges

  • Utiliser une Condition quand une Queue suffit.
  • Conserver un lock trop longtemps.
  • Faire du code lent ou bloquant à l’intérieur d’une section critique.

4. Niveau avancé

La synchronisation doit être pensée au niveau du design, pas ajoutée “à la fin”. Les meilleurs systèmes concurrents réduisent l’état partagé et utilisent des primitives explicites là où elles apportent vraiment une garantie.

À retenir
  • Pour producteur/consommateur, préfère une file bloquante à un protocole artisanal.
  • Le choix de la primitive dépend d’un besoin précis : exclusion, signal, quota, file, barrière.
  • Une synchronisation trop fine ou trop complexe devient vite illisible et fragile.
