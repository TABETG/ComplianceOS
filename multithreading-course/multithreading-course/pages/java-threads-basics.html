Java — Threads : bases indispensables

Thread, Runnable, Callable, Future, interruption, join, daemon threads et bonnes pratiques de base.

1. Introduction

Java fournit un écosystème très riche pour la concurrence. On peut commencer simplement avec Thread et monter jusqu’aux APIs de java.util.concurrent.

Pourquoi Java est fort sur ce sujet

  • Modèle mémoire défini.
  • Bibliothèque standard mature.
  • Bon outillage de debug et de profiling.
  • Utilisation massive en backend, batch, messaging et finance.

2. Niveau débutant

Thread, Runnable, Callable

TypeRôleRetour de valeurQuand l’utiliser

start() vs run()

start() crée un nouveau flux d’exécution. run() est un simple appel de méthode dans le thread courant.

public class ThreadBasics {
    public static void main(String[] args) throws Exception {
        Runnable task = () -> System.out.println("Je tourne dans " + Thread.currentThread().getName());

        Thread thread = new Thread(task, "worker-1");

        thread.start(); // lance le task dans un nouveau thread
        thread.join();  // attend la fin

        System.out.println("Main terminé");
    }
}

sleep(), join(), interruption

sleep() suspend temporairement le thread. join() attend la fin d’un autre thread. L’interruption est le mécanisme standard pour demander un arrêt coopératif.

public class InterruptExample {
    public static void main(String[] args) throws InterruptedException {
        Thread worker = new Thread(() -> {
            try {
                while (!Thread.currentThread().isInterrupted()) {
                    System.out.println("Traitement...");
                    Thread.sleep(500);
                }
            } catch (InterruptedException e) {
                // La meilleure pratique consiste à restaurer le flag
                Thread.currentThread().interrupt();
            }
            System.out.println("Arrêt propre");
        });

        worker.start();
        Thread.sleep(1200);
        worker.interrupt();
        worker.join();
    }
}

Daemon threads

Un daemon thread ne bloque pas l’arrêt de la JVM. Utile pour certains services auxiliaires, mais dangereux si on oublie qu’il peut être coupé brutalement à la fin du programme.

Pièges de débutant

  • Créer trop de threads.
  • Ignorer l’interruption.
  • Confondre concurrence et résultat ordonné.

3. Niveau intermédiaire

Callable et Future

Quand une tâche doit renvoyer un résultat, on utilise souvent Callable et Future, généralement via un executor.

import java.util.concurrent.*;

public class FutureExample {
    public static void main(String[] args) throws Exception {
        ExecutorService executor = Executors.newFixedThreadPool(2);

        Future future = executor.submit(() -> {
            Thread.sleep(300);
            return 42;
        });

        Integer result = future.get(); // bloquant : attend la fin si besoin
        System.out.println("Résultat = " + result);

        executor.shutdown();
    }
}

Bonnes pratiques

  • Éviter les threads manuels en production.
  • Donner des noms explicites aux threads si possible via ThreadFactory.
  • Toujours définir une stratégie d’arrêt.

4. Niveau avancé

Message important

Les primitives de base sont nécessaires pour comprendre, mais en entreprise on travaille surtout avec pools, futures, locks spécialisés, collections concurrentes, frameworks et runtimes applicatifs.

Cas réels

  • Traitement parallèle de lots.
  • Workers qui consomment une BlockingQueue.
  • Backend Spring Boot qui délègue des tâches IO-bound.
À retenir
  • start() crée un nouveau thread, run() non.
  • L’interruption est centrale pour l’arrêt propre.
  • En production, préfère ExecutorService à la création manuelle de threads.
