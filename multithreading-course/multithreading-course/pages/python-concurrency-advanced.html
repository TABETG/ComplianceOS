Python — Concurrency avancée

Synchronisation, Queue, futures, multiprocessing, asyncio et design propre.

1. Introduction

Python propose plusieurs primitives de synchronisation simples à prendre en main. Elles permettent déjà de construire beaucoup de solutions correctes sans tomber dans des designs trop fragiles.

import threading

counter = 0
lock = threading.Lock()

def increment():
    global counter
    for _ in range(100_000):
        with lock:
            counter += 1  # protégé contre les interleavings concurrents

threads = [threading.Thread(target=increment) for _ in range(4)]

for t in threads:
    t.start()
for t in threads:
    t.join()

print(counter)

3. Niveau intermédiaire

Queue pour producteur / consommateur

queue.Queue est souvent la meilleure solution au lieu de faire soi-même un buffer partagé avec Condition.

from queue import Queue
import threading
import time

jobs = Queue()

def producer():
    for i in range(5):
        jobs.put(f"job-{i}")
    jobs.put(None)  # sentinelle d'arrêt

def consumer():
    while True:
        item = jobs.get()
        try:
            if item is None:
                break
            print(f"Traitement de {item}")
            time.sleep(0.2)
        finally:
            jobs.task_done()

tp = threading.Thread(target=producer)
tc = threading.Thread(target=consumer)

tp.start(); tc.start()
tp.join(); tc.join()

concurrent.futures

ThreadPoolExecutor et ProcessPoolExecutor donnent une API plus propre que la gestion manuelle de threads ou de processus.

from concurrent.futures import ThreadPoolExecutor

def fetch(url):
    # simulation d'un appel réseau
    return f"fetched: {url}"

urls = ["a", "b", "c"]

with ThreadPoolExecutor(max_workers=4) as executor:
    results = list(executor.map(fetch, urls))

print(results)

4. Niveau avancé

multiprocessing

Pour du CPU-bound, plusieurs processus peuvent exploiter plusieurs cœurs et contourner la limitation du GIL, au prix d’un coût plus élevé et d’une communication plus complexe.

Recommandations de senior

  • Choisir l’outil en fonction du profil de charge, pas par habitude.
  • Préférer les queues et futures aux variables globales partagées.
  • Rester simple : beaucoup de problèmes se résolvent avec une queue, quelques workers et un protocole d’arrêt clair.
