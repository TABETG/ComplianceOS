Java — Concurrency avancée

Locks, JMM, volatile, atomic, concurrent collections, latches, barriers, futures et recommandations de senior.

1. Introduction

Le niveau avancé en Java commence quand on manipule sérieusement la synchronisation, le Java Memory Model, les primitives de coordination et les abstractions haut niveau.

2. Niveau débutant renforcé

synchronized

synchronized protège une section critique avec un verrou intrinsèque. Sur une méthode d’instance, le lock est porté par this. Sur une méthode statique, il est porté par la classe.

public class SafeCounter {
    private int value = 0;

    public synchronized void increment() {
        value++;
    }

    public synchronized int getValue() {
        return value;
    }
}

wait(), notify(), notifyAll()

Ces méthodes servent à la coordination sous monitor. Elles doivent être utilisées dans un bloc synchronisé sur le même objet. Aujourd’hui, on préfère souvent des abstractions plus robustes comme BlockingQueue ou Condition.

import java.util.concurrent.locks.ReentrantLock;

public class BankAccount {
    private final ReentrantLock lock = new ReentrantLock();
    private int balance = 0;

    public void deposit(int amount) {
        lock.lock();
        try {
            balance += amount;
        } finally {
            // Toujours libérer le lock dans finally
            lock.unlock();
        }
    }

    public int getBalance() {
        lock.lock();
        try {
            return balance;
        } finally {
            lock.unlock();
        }
    }
}

Collections concurrentes

ConcurrentHashMap, CopyOnWriteArrayList, BlockingQueue réduisent beaucoup de code fragile écrit “à la main”.

4. Niveau avancé

Java Memory Model

Le JMM définit les garanties de visibilité et d’ordre entre threads. Sans relation happens-before, un thread peut ne pas voir les écritures d’un autre comme tu l’imagines.

volatile

volatile garantit la visibilité d’une variable et interdit certains réordonnancements autour d’elle. En revanche, il ne rend pas un incrément atomique.

public class StopFlag {
    private volatile boolean running = true;

    public void stop() {
        running = false; // visible rapidement par les autres threads
    }

    public void work() {
        while (running) {
            // traitement
        }
    }
}

AtomicInteger

Pour un compteur atomique, AtomicInteger est adapté.

import java.util.concurrent.atomic.AtomicInteger;

public class AtomicCounter {
    private final AtomicInteger value = new AtomicInteger();

    public void increment() {
        value.incrementAndGet(); // opération atomique
    }

    public int getValue() {
        return value.get();
    }
}

ExecutorService, ScheduledExecutorService, CountDownLatch, CyclicBarrier

Ces outils servent à orchestrer des groupes de tâches proprement. Le CountDownLatch attend N événements ; le CyclicBarrier synchronise plusieurs participants sur plusieurs cycles.

CompletableFuture

CompletableFuture est très utile pour composer des traitements asynchrones, chaîner des étapes, gérer erreurs et fusion de résultats.

import java.util.concurrent.*;

public class CompletableFutureExample {
    public static void main(String[] args) {
        CompletableFuture userFuture =
            CompletableFuture.supplyAsync(() -> "Alice");

        CompletableFuture orderFuture =
            CompletableFuture.supplyAsync(() -> "Commande-42");

        String message = userFuture.thenCombine(orderFuture,
            (user, order) -> user + " -> " + order
        ).join();

        System.out.println(message);
    }
}

Recommandations de senior

  • Préférer les abstractions métier ou concurrentes éprouvées aux bricolages à base de wait/notify.
  • Mesurer avant d’optimiser.
  • Documenter explicitement les garanties thread-safe d’un composant.
  • En backend, attention aux interactions entre pool applicatif, base de données, réseau et pool de messages.
