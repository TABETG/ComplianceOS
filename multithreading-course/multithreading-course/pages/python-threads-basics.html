Python — Threads : bases indispensables

threading, start, join, daemon, partage d’état et compréhension claire du GIL.

1. Introduction

En Python, le module threading permet de lancer plusieurs threads. Le point central à comprendre est le GIL : il influence fortement ce que le threading peut réellement accélérer.

2. Niveau débutant

Création de threads

import threading
import time

def worker(name):
    print(f"{name} démarre")
    time.sleep(1)  # simulation d'attente I/O
    print(f"{name} termine")

t1 = threading.Thread(target=worker, args=("worker-1",))
t2 = threading.Thread(target=worker, args=("worker-2",), daemon=False)

t1.start()
t2.start()

t1.join()
t2.join()
print("Main terminé")

Daemon threads

Comme en Java, un thread daemon ne doit pas porter un travail critique qui doit absolument finir avant l’arrêt du processus.

Partage d’état

Les variables globales partagées entre threads peuvent produire des bugs subtils, même en Python.

3. Niveau intermédiaire

Le GIL expliqué simplement

Le Global Interpreter Lock fait qu’en CPython, un seul thread exécute du bytecode Python à un instant donné. Cela signifie :

  • Le threading est souvent utile pour des tâches IO-bound : réseau, disque, attente de service distant.
  • Il est généralement limité pour des tâches CPU-bound pures en Python pur.

Image mentale : plusieurs threads font la queue pour exécuter du code Python, mais pendant qu’un thread attend une I/O, un autre peut avancer.

Quand le GIL ne bloque pas tout

  • Quand un thread attend une I/O.
  • Quand des bibliothèques natives libèrent le GIL.
  • Quand on passe au multiprocessing au lieu du threading.

4. Niveau avancé

Choisir la bonne primitive

En Python, la vraie compétence n’est pas seulement “savoir créer un thread”, mais choisir entre threading, concurrent.futures, multiprocessing et asyncio.

Cas réels

  • Scraping et appels réseau concurrents : threading ou asyncio selon le design.
  • Traitements CPU lourds : multiprocessing ou extension native.
  • Workers légers en arrière-plan : ThreadPoolExecutor.
À retenir
  • Le threading Python est très utile pour l’I/O.
  • Le GIL limite les gains sur le CPU-bound en Python pur.
  • La bonne solution dépend du type de charge : IO-bound, CPU-bound, pipeline, attente d’événements.
