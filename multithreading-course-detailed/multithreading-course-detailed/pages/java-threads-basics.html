Java — Threads : bases

Les briques de base de la concurrence Java, avec syntaxe, comportements et pièges essentiels.

1. Introduction

Java propose un écosystème très riche pour la concurrence. La première étape consiste à maîtriser les briques de base : Thread, Runnable, Callable, Future, interruption, attente et coordination simple.

APIRôleQuand l’utiliser
ThreadReprésente un threadRarement directement en production.
RunnableTâche sans valeur de retourTravail simple exécuté par un thread ou un pool.
CallableTâche avec résultat et exceptionQuand on veut un retour de valeur.
FuturePromesse de résultat futurQuand on veut récupérer le résultat plus tard.

2. Niveau débutant

Thread et Runnable

public class BasicThreads {
    public static void main(String[] args) throws InterruptedException {
        Runnable job = () -> {
            System.out.println("Travail lancé dans " + Thread.currentThread().getName());
        };

        Thread worker = new Thread(job, "worker-1");
        worker.start(); // démarre un nouveau thread

        worker.join();  // le thread principal attend la fin du worker
        System.out.println("Fin du programme");
    }
}

start() démarre un nouveau thread. run() appelé directement ne crée pas de nouveau thread : il exécute la méthode dans le thread courant.

sleep()

Thread.sleep(...) suspend le thread courant pendant une durée donnée, mais ne libère pas un verrou déjà détenu.

join()

join() sert à attendre la fin d’un autre thread.

3. Niveau intermédiaire

Callable et Future

import java.util.concurrent.*;

public class FutureExample {
    public static void main(String[] args) throws Exception {
        ExecutorService executor = Executors.newSingleThreadExecutor();

        Callable<Integer> task = () -> {
            Thread.sleep(500);
            return 42;
        };

        Future<Integer> future = executor.submit(task);
        Integer result = future.get(); // bloquant jusqu'au résultat

        System.out.println("Résultat = " + result);
        executor.shutdown();
    }
}

Avec Callable, on peut retourner une valeur et lever une exception. Le Future permet de récupérer le résultat plus tard.

Interruption

L’interruption est un mécanisme de coopération. Un thread n’est pas “tué” brutalement : on lui demande de s’arrêter proprement.

while (!Thread.currentThread().isInterrupted()) {
    // travail par morceaux
}

Les méthodes bloquantes comme sleep() ou certaines opérations de queue peuvent lever InterruptedException. Bonne pratique : soit propager, soit rétablir le flag d’interruption.

4. Niveau avancé

Daemon threads

Un daemon thread est un thread d’arrière-plan qui ne retient pas la JVM en vie. Quand il ne reste plus que des daemon threads, la JVM peut s’arrêter. Ils sont utiles pour certaines tâches auxiliaires, mais dangereux si le traitement doit absolument finir.

Éviter les threads manuels

En production, on préfère éviter les new Thread(...) dispersés. Les raisons :

  • pas de centralisation des limites,
  • pas de monitoring simple,
  • risque d’explosion du nombre de threads,
  • arrêt difficile à piloter.

Cas réels

  • Consumer Kafka traité via plusieurs workers.
  • Traitement batch réparti via pool.
  • Backend Spring Boot déléguant des tâches I/O longues.

À retenir

  • Runnable = tâche sans retour ; Callable = tâche avec retour.
  • start() crée un nouveau thread ; run() seul n’en crée pas.
  • Interruption = coopération, pas arrêt forcé magique.
  • En prod, préfère pools et executors.
