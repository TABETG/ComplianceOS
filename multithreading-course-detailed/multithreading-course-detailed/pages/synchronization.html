Synchronisation et coordination

Exclusion mutuelle, coordination, files, signaux et patterns classiques avec exemples Java et Python.

1. Introduction

Synchroniser, ce n’est pas seulement “mettre un lock”. C’est choisir comment plusieurs threads se coordonnent pour accéder à une ressource, attendre un événement, se transmettre du travail ou limiter une capacité.

2. Exclusion mutuelle

L’exclusion mutuelle garantit qu’une seule exécution à la fois entre dans une section critique.

Java

Utiliser synchronized, ReentrantLock ou parfois des structures concurrentes qui encapsulent déjà la synchronisation.

Python

Utiliser Lock ou RLock, avec un bloc context manager pour garantir la libération du verrou même en cas d’erreur.

private final ReentrantLock lock = new ReentrantLock();

public void update() {
    lock.lock();
    try {
        // section critique
    } finally {
        lock.unlock();
    }
}
lock = threading.Lock()

Plus la primitive est spécifique, plus elle réduit le risque d’erreur. C’est pour cela qu’une queue thread-safe est souvent meilleure qu’un protocole maison de signaux et locks.

4. Producteur / consommateur

Pattern central : un ou plusieurs producteurs fabriquent des éléments, un ou plusieurs consommateurs les traitent. On ne veut ni perdre des messages, ni lire du vide, ni saturer la mémoire.

BlockingQueue<Job> queue = new LinkedBlockingQueue<>(1000);

// producteur
queue.put(job);

// consommateur
Job job = queue.take();
process(job);
queue = Queue(maxsize=1000)

queue.put(job)
job = queue.get()
process(job)
queue.task_done()

Pourquoi ce pattern est bon

  • transfert de données clair,
  • backpressure simple avec capacité maximale,
  • coordination robuste sans signaux maison fragiles.

5. Quand choisir quelle primitive

BesoinPrimitive recommandéePourquoi
Protéger un compteur simpleAtomicInteger / lockÉvite lost update.
Limiter N accès simultanésSemaphoreModélise directement le besoin.
Transférer du travailBlockingQueue / QueueMeilleur niveau d’abstraction.
Attendre la fin de N tâchesCountDownLatch / Future / as_completedPlus simple qu’un flag maison.
Diffuser un signal d’arrêtvolatile flag / EventLisible et adapté.

À retenir

  • Choisis la primitive la plus proche du besoin métier.
  • Une bonne synchronisation réduit le code de coordination manuelle.
  • Plus on réinvente un protocole, plus on augmente le risque de bug.
