Python — Threads : bases

Créer, lancer, attendre et coordonner des threads Python en comprenant vraiment le rôle du GIL.

1. Introduction

En Python, le multithreading passe souvent par le module threading. Il est très utile pour les tâches I/O-bound : appels réseau, lecture de fichiers, scraping, traitements d’attente. Pour les calculs CPU purs, il faut comprendre le GIL.

2. Niveau débutant

Créer un thread

import threading
import time

def worker(name):
    print(f"{name} démarre")
    time.sleep(1)
    print(f"{name} termine")

thread = threading.Thread(target=worker, args=("T1",))
thread.start()
thread.join()

start() et join()

  • start() lance réellement le thread.
  • join() attend sa fin.

Daemon threads

Comme en Java, un daemon thread sert à l’arrière-plan. Il peut être abandonné à l’arrêt du programme.

3. Partage d’état et pièges

import threading

counter = 0
lock = threading.Lock()

def increment():
    global counter
    for _ in range(10000):
        with lock:
            counter += 1

Le lock protège ici une section critique. Sans lui, le résultat final pourrait être incohérent.

Piège fréquent

Voir le GIL comme une garantie absolue de thread-safety est faux. Le GIL simplifie certaines choses au niveau de l’interpréteur CPython, mais il ne rend pas automatiquement la logique métier correcte ni toutes les opérations composées sûres.

4. GIL : explication simple

Le Global Interpreter Lock permet à un seul thread Python d’exécuter du bytecode Python à la fois dans CPython. Conséquence principale :

  • pour les tâches CPU-bound, le threading Python ne donne souvent pas de vrai gain de parallélisme CPU,
  • pour les tâches I/O-bound, le threading reste très utile car les threads peuvent attendre des I/O pendant que d’autres avancent.
Type de tâcheThreading PythonPourquoi
I/O-boundSouvent bon choixPendant l’attente I/O, d’autres threads peuvent progresser.
CPU-boundSouvent limitéLe GIL empêche un vrai parallélisme bytecode sur plusieurs cœurs.
Tâches mixtesÀ analyserLe profil exact décide entre threads, process ou asyncio.

5. Cas réels

  • Téléchargement de plusieurs pages web.
  • Écriture/lecture de fichiers multiples.
  • Petit worker d’arrière-plan sur des appels API.
  • Prétraitement concurrent léger côté ETL I/O.

À retenir

  • Le threading Python est très utile pour l’I/O.
  • Le GIL limite surtout le CPU-bound pur.
  • Utiliser des locks reste nécessaire quand l’état est partagé.
