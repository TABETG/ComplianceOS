Chapitre

Exercices

Questions, lecture de code, bugs et mini cas d’architecture.

1. Introduction

Cette page regroupe des exercices transverses, séparés du cours, pour valider la compréhension théorique, l’analyse de code, la correction de bugs et les arbitrages d’architecture.

2. Exercices débutant

Exercice 1 — Spring Boot

Explique en quelques lignes la différence entre Spring Framework et Spring Boot, puis cite le rôle de @SpringBootApplication.

Exercice 2 — IoC / DI

Réécris une classe qui instancie elle-même un dépôt avec new en injection par constructeur.

Exercice 3 — JPA

Crée une entité Book avec id, title, author et un repository avec findByTitleContainingIgnoreCase.

3. Exercices intermédiaires

Exercice 4 — AOP

Écris un aspect de logging pour toutes les méthodes d’un package service, puis explique pourquoi tu ne veux pas l’appliquer à tout le projet sans filtre.

Exercice 5 — @Transactional

Tu as un service qui crée une commande, débite un stock et écrit un audit. Décide où placer la transaction et justifie.

Exercice 6 — GraphQL

Construis un schéma GraphQL minimal avec une query et une mutation pour gérer des produits.

Exercice 7 — Kafka

Décris le design d’un événement OrderCreated avec une clé adaptée pour préserver l’ordre utile.

4. Exercices avancés

Exercice 8 — Bug JPA / N+1

Une API liste 200 commandes et charge le client pour chacune dans une boucle. Identifie le problème et propose au moins deux solutions.

Exercice 9 — Bug transactionnel

Une méthode annotée @Transactional est appelée depuis une autre méthode de la même classe et le comportement attendu n’a pas lieu. Explique pourquoi.

Exercice 10 — Kafka vs RabbitMQ

Tu dois choisir une technologie pour : a) notifications asynchrones métiers ciblées, b) conservation rejouable d’un flux d’événements. Donne le bon choix et justifie.

Exercice 11 — Mini architecture

Conçois l’architecture d’un service e-commerce : REST ou GraphQL pour le front, JPA pour la persistence, Kafka ou RabbitMQ pour les événements. Justifie chaque décision.

5. À retenir

Le but n’est pas seulement de “savoir réciter”, mais de relier le concept, le code, le comportement runtime et le choix d’architecture.
