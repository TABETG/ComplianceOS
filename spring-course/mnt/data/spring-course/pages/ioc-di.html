Chapitre

IoC / Inversion of Control / Dependency Injection

Comprendre le conteneur Spring, les beans, les scopes et l’injection propre.

1. Introduction

IoC signifie Inversion of Control. Au lieu qu’une classe crée elle-même ses dépendances, elle les reçoit de l’extérieur, ici via le conteneur Spring.

Analogie : au restaurant, le cuisinier ne fabrique pas ses casseroles. Il les reçoit déjà prêtes. En IoC, une classe reçoit ce dont elle a besoin au lieu de tout construire elle-même.

C’est important car cela améliore la testabilité, le découplage et la maintenabilité.

2. Niveau débutant

Bean : objet géré par Spring.

Annotations clés : @Component, @Service, @Repository, @Controller.

AnnotationRôleQuand l’utiliser
@ComponentComposant génériqueClasse technique sans sémantique métier forte
@ServiceLogique métierUse cases, orchestration
@RepositoryAccès aux donnéesDAO, intégration persistence
@Controller / @RestControllerEntrée HTTPAPI et web
@Service
public class InvoiceService {
    private final TaxCalculator taxCalculator;

    public InvoiceService(TaxCalculator taxCalculator) {
        this.taxCalculator = taxCalculator;
    }
}

Piège débutant : injection par champ avec @Autowired partout. Ça marche, mais c’est moins testable et plus difficile à raisonner.

3. Niveau intermédiaire

Trois styles d’injection existent :

TypeAvantagesInconvénientsRecommandation
ConstructeurImmutabilité, testabilité, dépendances explicitesConstructeurs longs si classe mal découpéeÀ privilégier
SetterUtile pour dépendances optionnellesObjet potentiellement incompletUsage limité
ChampÉcriture rapideTestabilité faible, dépendances cachéesÀ éviter

Quand plusieurs beans ont le même type, Spring a besoin d’aide :

@Bean
@Primary
public PaymentGateway stripeGateway() { ... }

@Bean
public PaymentGateway paypalGateway() { ... }

@Service
public class BillingService {
    private final PaymentGateway paymentGateway;

    public BillingService(@Qualifier("paypalGateway") PaymentGateway paymentGateway) {
        this.paymentGateway = paymentGateway;
    }
}

Scopes utiles : singleton par défaut, prototype rarement, request surtout en web, session plus rare dans les architectures modernes stateless.

4. Niveau avancé

Le conteneur Spring construit un graphe de dépendances. Si A dépend de B et B dépend de A, tu peux tomber sur une dépendance circulaire. C’est souvent un signal de mauvais découpage.

Piège subtil : utiliser trop de beans “utilitaires” transverses qui deviennent des points d’accumulation. Une bonne architecture garde des responsabilités claires.

Cycle de vie : instanciation, injection, callbacks d’initialisation, utilisation, puis destruction éventuelle. Comprendre cela aide à gérer correctement les ressources coûteuses.

@Component
public class CacheWarmupBean {

    @PostConstruct
    public void init() {
        // Exécuté après injection des dépendances
    }

    @PreDestroy
    public void cleanup() {
        // Exécuté avant fermeture du contexte
    }
}

Recommandation tech lead : l’injection par constructeur doit rendre les dépendances métier visibles. Si ton constructeur a 12 paramètres, ce n’est pas un problème d’injection, c’est un problème de design.

5. Exemples de code

// Fichier : NotificationService.java
@Service
public class NotificationService {
    private final MailClient mailClient;
    private final SmsClient smsClient;

    public NotificationService(MailClient mailClient, SmsClient smsClient) {
        this.mailClient = mailClient;
        this.smsClient = smsClient;
    }

    public void sendWelcomeMessage(User user) {
        // Le service orchestre, il ne crée pas ses dépendances.
        mailClient.send(user.email(), "Bienvenue !");
        smsClient.send(user.phone(), "Votre compte est activé");
    }
}

6. À retenir

  • Le conteneur Spring gère les beans et leurs dépendances.
  • L’injection par constructeur est le standard recommandé.
  • @Primary et @Qualifier résolvent les ambiguïtés.
  • Les scopes doivent être choisis avec retenue.
  • Une dépendance circulaire est souvent un défaut d’architecture.

7. Exercices

Débutant

Transforme une classe qui fait new EmailSender() en classe injectable par Spring.

Intermédiaire

Deux implémentations d’une même interface existent. Force l’une par défaut avec @Primary puis injecte explicitement l’autre avec @Qualifier.

Avancé

Analyse un cas de dépendance circulaire entre OrderService et PaymentService, puis propose un refactoring.
